# Ten-minute event rehearsal

Use a fresh practice event, then create a separate real event with the actual pouring key.

1. Open `/host`, sign in, name the practice event and assign all eight wine types exactly once. Check the order against numbered bottle covers. Save the key.
2. Keep the big-screen display closed for the first rehearsal. Share the invitation link or scan the host’s join QR with an actual iPhone and Android phone over the event Wi-Fi; enter different names and optionally draw icons. Try Undo, Clear and a different ink color. Reopen/refresh each phone and confirm the original seat and saved drawing return. Existing guests can use Draw or edit your icon on their scorecards. Open the invitation in a separate browser and use Recover my seat with the same existing display name and host approval; verify the existing scorecard returns and the host count does not increase. Older seats recover through the same host approval flow.
3. Start round 1. Confirm both phones update automatically, and future rounds do not appear. Save a guess, decimal rating and dictated note; wait for “Saved”. Briefly disconnect one phone, edit and reconnect. Confirm that the draft saves without false “Saved” feedback.
4. Open each next round. Return to round 1 and edit it. Repeat a wine type in two rounds; confirm the conflicting round numbers are visible and final submission stays blocked. Correct it and complete all eight rounds, then submit.
5. Change a submitted card to a duplicate; verify it returns to draft status. Correct and resubmit. Leave one practice guest incomplete; verify the host names that person before locking. Exercise the explicit override on this practice event.
6. Lock submissions. Confirm both phones switch from scorecards to the first guess breakdown without refreshing. Attempts to save cannot change locked scorecards. Wine identities and ratings wait for their respective Reveal action. Notes remain private.
7. Walk through all eight reveals: open the next round’s guesses, reveal its wine and producer, check correct highlights and group ratings. On one phone revisit round 1 while the host continues; confirm it stays on that round and cannot open future results. Tap Follow host to return. Refresh the host and both phones partway through and confirm the saved stage resumes. Open the summary, inspect ties and missing entries, and download the CSV privately.
8. Restart/redeploy the configured app, revisit the practice event and verify the same saved results. Confirm `/api/health` reports PostgreSQL at the hosted URL. Confirm the main haroldvazquez.com website still opens.
9. Create the real event with the real key. Confirm QR points at the final HTTPS domain, if using a big screen, click Open big-screen display, connect laptop power, disable screen sleep and verify text from the back of the room. Close/reopen that window and confirm it does not change the event; keep host password private, and have paper backup scorecards available.

Phone-specific checks: Safari/Android decimal keyboard, notes dictation, comfortable tap targets, portrait layout, refresh recovery, lock behavior and camera QR scanning. These require real devices and were not performed by automated Chromium tests.
